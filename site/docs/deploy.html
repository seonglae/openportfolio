Deploying

The dashboard and the backend deploy together in one click. The sync loop does not, and that is a property of the design rather than a gap.

Deploy to Vercel

What the button does

It clones the repository into your Git account and creates a Vercel project whose build command is in vercel.json: 

npx convex deploy --cmd-url-env-var-name VITE_CONVEX_URL --cmd 'pnpm --filter openportfolio-browser build'

One command does both halves: it pushes the schema, functions and indexes to your Convex deployment, then builds the browser with VITE_CONVEX_URL already pointing at it. The --cmd-url-env-var-name flag matters, because the default variable is CONVEX_URL and Vite only exposes names prefixed VITE_.

The two variables it asks for

Variable Where it comes from
CONVEX_DEPLOY_KEY A production deploy key from the Convex dashboard. Or install the Convex integration from the Vercel Marketplace and let it create the project for you.
VITE_CLERK_PUBLISHABLE_KEY Your Clerk application. Publishable keys are public by design; the secret never appears here.

Then one command, on the Convex side

Convex has to be told which issuer to trust, and this is a Convex deployment variable rather than a Vercel one, so the button cannot set it: 

npx convex env set CLERK_ISSUER_URL https://your-app.clerk.accounts.dev
npx convex run tenants:create '{"slug":"home","name":"Home","baseCurrency":"GBP"}'

Never set OPENPORTFOLIO_DEV_TENANT on a deployment with a public URL. It is the localhost escape hatch: while it is set, every unauthenticated visitor is scoped to that book. A deployment with Clerk configured and the hatch unset is private; the header says which of the two you are looking at, so you do not have to guess.

What one click cannot cover

sync-worker.mts reads your accounts through the venue adapters, and agent-worker.mts dispatches model work to an agent CLI you are already signed in to. There is no provider key to hand a serverless function, and no signed-in CLI inside one. Those run on your machine, against your own logins, which is the same reason there is no hosted version of this to sign up for.

The deployed half is not a shell without them. Convex runs its own crons, so forecasts still resolve and Brier scores still update on schedule; a manual holdings file still produces a net worth. Point the worker at the same deployment when you want the accounts to refresh themselves.

Why there is no Cloudflare button

Cloudflare's deploy button supports Workers applications only, and its monorepo mode requires the application to be fully isolated inside its subdirectory, dependencies included. browser/ imports convex/_generated from the repository root and two workspace packages, so it fails that test. Cloudflare Pages remains a fine manual target, and this marketing site is deployed to it with pnpm site:deploy.
